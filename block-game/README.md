# ブロックの世界（3Dブロックゲーム）

スマホの横画面で遊ぶ、一人称のボクセルゲーム。ノイズで生まれた地形を歩いて、木を切って、
ブロックを積む。牛と羊がうろついています。

## 遊ぶ

**https://gongakoronda825-hub.github.io/-/block-game/play/**

インストールも登録も要りません。スマホは横向きにしてください。

配信しているのは `play/index.html` の1枚だけです。外部への通信がまったく無い
（three.js もテクスチャも全部この中）ので、ダウンロードしてオフラインで開いても
同じように動きます。

開発するときは Vite の開発サーバーを使います。

```
npm install
npm run dev      # vite --host。表示された http://192.168.x.x:5173 にスマホからアクセスする
```

実機での確認が前提です。DevTools のモバイルエミュレーションは、マルチタッチの
挙動が実機と違います。

## 操作

| したいこと | 操作 |
|---|---|
| 移動 | 画面左下のスティック（左半分ならどこを触っても効く） |
| 見まわす | 画面右半分をなぞる。上下は ±89° で止まる |
| ジャンプ | 「ジャンプ」を1回タップ。接地しているときだけ跳べる |
| とぶ | 「ジャンプ」を2回連打。もう一度2回連打で解除 |
| 上下（飛行中） | 飛行中だけ現れる ▲ ▼ を押している間 |
| ブロックを選ぶ | 画面下中央のインベントリをタップ |
| こわす | 中央の ＋ を合わせて「こわす」 |
| おく | 面を狙って「おく」。その面の隣に、選んでいるブロックが積まれる |

PC で確認するとき用に、WASD／矢印キーでの移動、マウスドラッグでの視点操作、
スペースでジャンプ、左Shiftで下降、数字キー 1〜5 でブロック選択も受け付けます。

とどく範囲（リーチ）は5ブロック。空を向いていたり遠すぎたりすると、
ボタンを押しても何も起きません。1ブロックの段差はジャンプしなくても歩けば登ります。
飛行中も当たり判定は生きているので、壁はすり抜けられません。

牛と羊には手を出せません。歩き回っているだけの、風景の一部です。

## 中身

Three.js + TypeScript + Vite。物理エンジンは使わず、当たり判定は自前の AABB です。

```

├── main.ts                        ゲームループ
├── core/config.ts                 定数（リーチ・重力・地形・木・動物）
├── core/Renderer.ts               シーン / カメラ / フォグ / リサイズ
├── physics/VoxelBody.ts           AABB × ボクセルの当たり判定（プレイヤーと動物で共有）
├── world/blocks.ts                ブロック定義とテクスチャアトラス
├── world/Chunk.ts                 チャンクのボクセル（Uint8Array）
├── world/ChunkMesher.ts           面カリングによるメッシュ生成
├── world/ChunkManager.ts          周囲のチャンクの生成 / メッシュ化 / 破棄
├── world/World.ts                 チャンク集合の窓口（ワールド座標で読み書き）

├── worldgen/TreeGenerator.ts      木の配置と構造

├── entities/Animal.ts             パッシブなうろつき AI
├── entities/animals.ts            種別定義（牛・羊）
```

### あとから触るときに知っておくとよいこと

**ワールドはチャンク（16×16列 × 高さ64）で、ボクセルは `Uint8Array`。**
1ブロック1 Mesh では広いワールドが持たないので、チャンク単位で1つの
`BufferGeometry` に結合しています。

**面カリングの条件は「隣が不透明でなければ描く」の1つだけ**です。これだけで
「空気に面した面は描く」「葉ごしに見える固体の面は消さない」「葉同士の面も描く」が
同時に満たせます。マテリアルを1つに束ねる必要があるので、テクスチャは
16×16タイルを並べたアトラスをその場で描いて UV で引いています。

**チャンクは2段階で作ります。** ①データだけ生成（隣を一切参照しないので順不同でよい）
→ ②4隣接が生成済みになったらメッシュ化。こうしないと継ぎ目の面カリングが狂います。
ブロックを壊す/置くとき、それがチャンクの端なら隣も再メッシュします。

**レイキャストはヒット点から座標を復元します。** メッシュが結合されたので
「Mesh ごとに座標を持たせる」方式は使えません。
壊す先は `floor(point - n * 0.5)`、置く先は `floor(point + n * 0.5)`。
0.5 ずらすのは、ヒット点が境界にあって `floor` が揺れるのを避けるためです。

**地形も木も `(seed, x, z)` の純関数**です。チャンクをどの順で作っても、離れて
戻ってきても同じ地形になります。木がチャンクをまたぐ問題は、保留キューではなく
**チャンクを外側に広げて走査し、はみ出した分を捨てる**方法で解いています。
隣チャンクも自分の走査で同じ木を同じ形に描くので、生成順に関係なく欠けません。

**当たり判定は `VoxelBody` 1つ**で、プレイヤーも動物も同じ実装を通ります。
X → Y → Z と軸ごとに分離して解きます（まとめて解くと角で引っかかる）。
`position` は足元の中心です。

**動物の高さはスクリプトで動かしません。** 重力と衝突に任せ、坂は
オートステップ（進行方向が塞がれていて1つ上が空いていれば1段上る）で登ります。
AI の判断は 0.4 秒ごと、物理は毎フレームです。

**動物は保存しません。** 離れれば消え、範囲内で上限まで湧き直します。地形や木と違い
決定論も要りません（動くし一時的な存在なので）。

**移動と重力はデルタタイムで計算します。** タブから戻ったときに大きく飛んで
壁をすり抜けないよう、1フレームの dt は 0.05 秒で頭打ちにしてあります。
