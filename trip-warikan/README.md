# Trip割り勘

旅行中の立て替え払いを記録して、旅行が終わったときに
**誰が誰にいくら払えば精算が終わるのか** を自動で出すアプリ。

海外旅行での「とりあえず誰かが払っておく」を、その場で数秒で記録することだけを目的にしている。
ログインもサーバーもなく、通信が切れていても全機能が動く。

## 動かす

```sh
npm install
npm start          # QR コードを Expo Go で読み取る
npm run ios        # iOS シミュレータ
npm run android    # Android エミュレータ
npm run web        # ブラウザで確認する
```

```sh
npm test           # 精算ロジックのテスト
npm run typecheck  # 型チェック
```

## 画面

| 画面 | できること |
| --- | --- |
| ホーム | 旅行の一覧、新しい旅行の作成 |
| 新しい旅行 | 旅行名・通貨・メンバー（2人以上）の登録 |
| 旅行詳細 | 各メンバーの収支、支払い履歴（新しい順）、支払いの追加 |
| 支払いを追加 / 詳細 | 支払った人・金額・内容・支払い対象者の入力、編集、削除 |
| 精算結果 | 誰から誰にいくら送るか、精算完了までの各自の状況 |

## 中身

計算ロジックは UI から完全に切り離してある。`src/lib/` は React に一切依存しない純粋関数だけ。

```
src/
  lib/
    settlement.ts   収支の計算と、送金リストの算出（このアプリの核）
    money.ts        最小単位への変換と端数の配分
    currency.ts     通貨ごとの桁数と表示形式
    validation.ts   入力チェック（日本語のエラー文言）
    confirm.ts      取り消せない操作の確認ダイアログ
  storage/          AsyncStorage への保存・復元（読み込み時に形を検証する）
  store/            旅行データの状態管理。更新と保存を必ずセットで行う
  screens/          画面
  components/       画面をまたいで使う部品
__tests__/          精算ロジックのテスト
```

### 金額は必ず整数で扱う

**このアプリで一番壊れやすいのは端数処理**なので、金額計算はすべて
「最小単位（円・セント）の整数」で行っている。浮動小数のまま足し引きすると
1円ズレが出て、収支の合計が 0 にならなくなり、精算アルゴリズムが破綻する。

割り切れないときは端数を先頭の人から1ずつ配る（`splitEvenly`）。
これにより **配分の合計は必ず元の金額と一致し、収支の合計は必ず 0 になる**。

例：20,000円を3人で割ると 6,667 / 6,667 / 6,666 円。合計はちょうど 20,000円。

小数を使わない通貨（JPY / KRW / TWD / VND）は 0 桁、USD / EUR / GBP は 2 桁として扱う。

### 支払った人も負担者に含める

支払った人が支払い対象者にチェックされていれば、その人も負担者として計算する。
4人分 12,000円を A が払い、4人全員が対象なら、A の実質的な立て替えは 9,000円。

### 精算は送金回数が少なくなるようにまとめる

各メンバーの収支をそのまま並べるのではなく、受け取る側・支払う側を金額の大きい順に
並べて大きいもの同士から消し込む。送金回数は必ず（関係者数 − 1）回以下に収まる。

## テストの状況

`npm test` の 36 件が通っている（仕様書のテスト1〜6、端数処理、精算アルゴリズム、
入力チェック、通貨の表示）。

加えて、web ビルドをブラウザで自動操作して、旅行作成 → 支払い3件の登録 → 精算結果 →
編集 → 削除 → 再起動後のデータ復元まで一連の流れを 35 項目確認済み。

## MVP の範囲外

仕様どおり、以下はまだ入れていない。

- サーバー同期・ログイン
- 旅行の削除・編集
- 通貨換算（1つの旅行では1つの通貨のみ）
- 支払いの写真添付やメモ
