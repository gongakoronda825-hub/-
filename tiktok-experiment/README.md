# TikTok改善実験トラッカー

TikTokの改善実験を「仮説 → 検証 → 改善」の形で記録・分析するローカルアプリです。
就活のガクチカで、取り組みを**数字で**説明できる記録を残すことを目的にしています。

- Python + Streamlit。データはCSVで、自分のPCの中だけに保存されます（DB・通信なし）
- 最後に、面接用の素材をMarkdownファイルで書き出せます

## iPhoneで使う（おすすめ）

`web/index.html` は、同じ機能をiPhone向けにしたWeb版です。claude.ai 上に公開してあり、
URLをSafariまたはClaudeアプリで開くだけで使えます（claude.ai へのログインが必要）。

- 記録は claude.ai のサーバーに保存されます。iPhoneのデータを消しても残ります
- 読み書きできるのは持ち主本人だけです
- 投稿を**ジャンル（雑学／イベント告知／グッズ紹介）**で分けて記録します。ベースラインもジャンル別に持ち、各投稿は同じジャンルの基準と比べます。ジャンルをまたいで比べるときは、それぞれの基準からの伸び率（%）を使います
- ⑤の画面から、バックアップ（JSON）と投稿ログ（CSV）をファイルに保存・復元できます

以下は、PCで動かすStreamlit版の手順です（Streamlit版はジャンル分けに未対応です）。

## 起動手順（PC・Streamlit版）

Python 3.10 以上が必要です。

```bash
# 1. このフォルダに移動
cd tiktok-experiment

# 2. 必要なライブラリを入れる（最初の1回だけ）
pip install -r requirements.txt

# 3. 起動
streamlit run app.py
```

ブラウザが自動で開きます（開かなければ http://localhost:8501 を開いてください）。
終了するときは、ターミナルで `Ctrl + C` を押します。

> 仮想環境を使う場合は、手順2の前に `python -m venv .venv` → 
> `source .venv/bin/activate`（Windowsは `.venv\Scripts\activate`）を実行してください。

## 画面と使い方

左のメニューから5つの画面を切り替えます。おすすめの流れは ① → ② →（③を毎投稿）→ ④を毎月 → ⑤ です。

| 画面 | やること |
|---|---|
| ① 現状の記録 | 日付・フォロワー数・直近10本の平均再生数・平均視聴維持率・平均保存数を登録。月初などに定期的に登録すると、推移がグラフで見えます。同じ日付で登録すると上書き。 |
| ② 目標設定 | 指標を1つ（再生数／視聴維持率／保存数／フォロワー増加数）選び、現在値・目標値・期限を入力。達成率（現在値÷目標値）と残り日数を表示。現在値は①の記録から候補が自動で入ります。 |
| ③ 投稿ログ | 投稿ごとに「今回変えた点（1つだけ）」と変更カテゴリ・仮説を記録。変えた点が**空欄**、または**読点（、）で複数**書かれていると警告が出ます。数値は投稿48時間後に入力する前提で、未入力の投稿を画面上部にまとめて知らせます。 |
| ④ 月次振り返り | 月を選ぶと、変更カテゴリごとの平均再生数をベースラインと比較。投稿（施策）ごとに「効いた／効かなかった」を自動で並べます。「効いた施策／効かなかった施策／来月試すこと」を各3行で書いて保存。 |
| ⑤ ガクチカ素材の出力 | ベースライン → 目標 → 実施した施策 → 結果の数字 → 学び の順でMarkdownを作成。`exports/` に保存、またはダウンロード。面接用の骨子（下書き）も付きます。 |

### 計算のルール

- **月次振り返りで使うベースライン**: その月の月初以前で最新の①の記録。無ければ最初の記録。
- **効いた／効かなかった**: 投稿の再生数がベースラインの平均再生数より +10% 以上なら「効いた」、それ未満は「効かなかった」。しきい値は画面のスライダーで変えられます。
- **再生数が未入力の投稿**は集計から外します。
- **フォロワー増加数**の現在値の候補 = 最新のフォロワー数 − 最初の記録のフォロワー数（目標設定後の更新では、目標を立てた日時点からの増加）。

## データの保存場所

```
tiktok-experiment/
├── data/            ← 入力したデータ（CSV, UTF-8 BOM付きなのでExcelでもそのまま開けます）
│   ├── baseline.csv   ① 現状の記録
│   ├── goals.csv      ② 目標（履歴も残る）
│   ├── posts.csv      ③ 投稿ログ
│   └── reviews.csv    ④ 月次振り返り
└── exports/         ← ⑤ で書き出したMarkdown
```

バックアップは `data/` フォルダをコピーするだけです。
`data/` と `exports/` の中身は `.gitignore` で除外していて、Gitにはコミットされません
（このリポジトリは GitHub Pages で公開されるため、個人の数字が外に出ないようにしています）。

## ファイル構成（設計）

```
tiktok-experiment/
├── app.py                     起動ファイル。5画面をナビゲーションに登録するだけ
├── requirements.txt
├── tiktok_tracker/
│   ├── config.py              定数（CSVの列定義、カテゴリ、指標、48時間など）
│   ├── storage.py             CSVの読み書き（列の補完・型そろえ）
│   ├── logic.py               計算（変えた点チェック、未入力検出、達成率、月次集計）
│   ├── report.py              ガクチカ用Markdownの組み立て
│   └── screens/               画面ごとの表示（①〜⑤）
│       ├── baseline.py / goal.py / posts.py / review.py / export.py
│       └── _common.py
└── tests/                     pytest（計算・Markdown・各画面の描画）
```

画面（`screens/`）は入出力だけを担当し、計算は `logic.py`、保存は `storage.py` に分けています。
集計ルールを変えたいときは `logic.py`、カテゴリや指標を増やしたいときは `config.py` を直します。
