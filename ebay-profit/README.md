# eBay 着地利益ツール

eBay日本輸出の「着地利益（手取り円）」を弾いて、仕入れ候補に優先順位を付けるための個人用PWA。
iPhone（ホーム画面に追加）とPCの同じURLで動く。

需要データを"生成"する道具ではない。**手に入る合法データ＋手動情報から、着地利益を正確に計算して並べ替える**道具。

```
着地利益_円 = 売上 − eBay手数料 − 入金手数料 − 原価 − 国際送料 − 雑費
```

## できること

| | |
|---|---|
| ダッシュボード | 候補を総合スコア降順に表示。列ソート・利益/ROI下限フィルタ・リスク除外。モバイルはカード表示に自動切替 |
| 候補詳細 | 着地利益の内訳を1項目ずつ表示、損益分岐の売値、スコア内訳、履歴の推移 |
| 候補追加 | 手動入力（入力しながらリアルタイム試算）/ Terapeak CSV 一括取り込み / 楽天・Yahoo!から仕入れ候補検索 |
| ウォッチリスト | 保存候補を最新の為替・相場で一括再計算。前回記録との差分としきい値アラート |
| 設定 | 料率・送料表・スコア重みをUIから編集。JSONバックアップ / 復元 |

## データ源について（設計上の前提）

eBayの実売データは意図的に閉じられている。この前提に合わせて設計してある。

| 用途 | ルート | 取り方 |
|---|---|---|
| eBay実売（sell-through率・平均価格・販売数） | Terapeak Product Research | 画面からCSVエクスポート → 取り込み |
| eBay出品中の相場帯・競合数 | Browse API | サーバーレス関数経由 |
| 日本仕入れ値（自動） | 楽天市場 / Yahoo!ショッピング API | サーバーレス関数経由 |
| 日本仕入れ値（API無し媒体） | メルカリ・ヤフオク・駿河屋など | **手動でURL/価格を貼り付け** |
| 為替 | 無料の為替API | サーバーレス関数経由 |
| 国際送料 | 各社料金表 | `config/shipping.json` に手動で保持 |

**やっていないこと**：eBayの売却済みページ、メルカリ、ヤフオクの自動スクレイピング。規約違反であり、すぐ壊れるため実装に含めていない。
Finding API（廃止済み）と Marketplace Insights API（新規開放停止）にも依存していない。

## セットアップ

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 計算エンジンの単体テスト
npm run build    # 型チェック + 本番ビルド（dist/）
```

外部APIを使わなくても、手動入力だけで着地利益の計算・スコアリング・ウォッチリストは全部動く。

## デプロイ（Vercel の例）

1. このリポジトリをVercelにインポートし、**Root Directory を `ebay-profit` に設定**する
2. 環境変数を登録する（`.env.example` 参照）。`VITE_` プレフィックスは付けないこと — 付けるとバンドルに埋め込まれて露出する

   | 変数 | 用途 |
   |---|---|
   | `EBAY_CLIENT_ID` / `EBAY_CLIENT_SECRET` | Browse API（出品中の相場・競合数） |
   | `RAKUTEN_APP_ID` | 楽天市場の仕入れ候補検索 |
   | `YAHOO_APP_ID` | Yahoo!ショッピングの仕入れ候補検索 |

3. デプロイ。`/api/*` が自動でサーバーレス関数になる
4. iPhoneのSafariでURLを開き、共有 → **「ホーム画面に追加」**

Netlify / Cloudflare Pages を使う場合は `api/*.ts` をその環境の関数形式に移し、設定画面の「APIベースURL」をそのパスに向ける。

### iOS のストレージについて（重要）

データは端末内（IndexedDB）にのみ保存される。**Safariのタブに置いたままだと約7日で消えることがある。**

- 必ず「ホーム画面に追加」して使う
- 設定画面から定期的にJSONバックアップを書き出す（端末間の移行にも使える）

## 料率・送料は必ず現行値に更新すること

`config/rates.json` と `config/shipping.json` の初期値は**雛形**であり、実際の料金表を確認して上書きすることが前提。
eBayの手数料、カテゴリ別料率、各社の国際送料、為替はいずれも変動する。値はコードに直書きせず、設定画面か config で管理する。

初回起動時に config の値が IndexedDB にコピーされ、以後は設定画面の値が使われる。config を直したあと反映したい場合は設定画面の「設定を初期値に戻す」を押す。

## 構成

```
src/domain/       profit.ts（着地利益）, score.ts（スコア）, risk.ts, evaluate.ts, types.ts, __tests__/
src/datasources/  terapeakCsv.ts, browseApi.ts, suppliers.ts, fx.ts, http.ts
src/storage/      db.ts（Dexie/IndexedDB）, backup.ts（JSON入出力）
src/ui/           Dashboard, CandidateDetail, AddCandidate, Watchlist, Settings
api/              サーバーレス関数（browse / rakuten / yahoo / fx）。APIキーはここだけ
config/           rates.json, shipping.json, scoring.json, risk.json（初期値の雛形）
```

計算の心臓部（`domain/profit.ts` と `domain/score.ts`）は副作用のない純関数で、単体テストで固定してある。数字がずれたらここのテストが落ちる。

## スコアリング

```
総合スコア = 需要×w1 + 利益×w2 + 回転×w3 + 競合×w4 − リスク減点×w5
```

データが取れていないサブスコア（需要・回転・競合）は、重みごと分母から外して計算する。0点扱いにして未調査の候補を不当に沈めないため。
代わりに一覧へ「データ不足」バッジを出すので、スコアだけを見て未調査の候補を上位と誤読しないこと。

リスク（VeRO/ブランド規制、CITES、食品・化粧品、電波法/PSE、リチウム電池、模造品、カテゴリ制限）はキーワードから**候補を提示するだけ**で、確定は手動チェックで行う。

## 注意

- Terapeakの集計には個別取引の粒度がない。数字は「参考」であり、最終判断は人がやる
- 自分専用のツールとして作ってある。認証も複数ユーザー対応も無い。同期が必要なら保存層（`src/storage/`）をホスト型DBに差し替え、パスコードで保護すること
